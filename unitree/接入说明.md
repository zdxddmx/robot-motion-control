# 与 Unitree SDK2 的接入说明

> ⚠️ **先读这段**：本项目**没有使用过 Unitree SDK2**，也没有接过 Unitree 的机器狗/人形。
> 本文写的是**接口形态的对应关系**与**接入步骤**，属于"读文档 + 按规范设计"的成果，
> **不是集成经验**。面试时请如实区分。

---

## 一、为什么要写这份文档

岗位要求基于 Unitree SDK2 做二次开发。我手上没有机器人与 SDK 环境，
所以选择了一条更实在的路：

> **把"与 SDK 无关的那一半"做扎实** —— 关节控制、插值、动作序列、安全机制、
> 状态监控。这些是二次开发里真正花时间、也最容易出事故的部分（本项目就抓出了
> "首拍位置阶跃"和"梯形曲线在不可行区间退化"两个真问题）。

然后**把与 SDK 的耦合收敛到一个接口**（`RobotPort`），
换机器人时只需要写一个 DDS 后端，其余逻辑不动。

---

## 二、接口对应关系

| Unitree SDK2 | 本项目 | 说明 |
|---|---|---|
| `unitree_hg::msg::LowCmd` / `unitree_go::msg::LowCmd` | `motion::JointCommand` | 每个电机的 `q / dq / tau / kp / kd` |
| `LowState`（`motor_state[]`） | `motion::JointState` | `q / dq / tau / temperature` |
| `LowState.imu_state` | `RobotState.imu_rpy / imu_gyro / imu_acc` | 姿态与角速度 |
| `SportClient`（`StandUp` / `Move` / `Damp` / `StopMove` …） | `RobotController::stand() / walk() / damp()` + `RobotPort::switch_service()` | 高层运动服务 |
| `unitree_sdk2py` 的 `ChannelPublisher` / `ChannelSubscriber` | `RobotPort::write_command()` / `read_state()` | 发布订阅 |
| （无对应） | `motion::SafetyChecker` | **SDK 不提供安全机制，必须自己写** |

## 三、接入步骤（伪代码）

```cpp
// 1) 实现一个 DDS 后端
class UnitreeDdsPort : public motion::RobotPort {
public:
    bool connect() override {
        // 初始化 DDS 通道（domain id、topic 名按机型文档填）
        cmd_pub_ = std::make_unique<ChannelPublisher<LowCmd>>("rt/lowcmd");
        state_sub_ = std::make_unique<ChannelSubscriber<LowState>>("rt/lowstate");
        cmd_pub_->InitChannel();
        state_sub_->InitChannel([this](const void *msg) {
            const auto *s = static_cast<const LowState *>(msg);
            latest_ = to_robot_state(*s);      // LowState -> RobotState
            has_new_ = true;
        });
        return true;
    }

    bool write_command(const std::vector<motion::JointCommand> &cmd) override {
        LowCmd out{};
        // 注意：不同机型的关节索引映射不同，务必按机型文档核对
        for (size_t i = 0; i < cmd.size() && i < kMotorNum; ++i) {
            out.motor_cmd[i].q   = cmd[i].q;
            out.motor_cmd[i].dq  = cmd[i].dq;
            out.motor_cmd[i].tau = cmd[i].tau;
            out.motor_cmd[i].kp  = cmd[i].kp;
            out.motor_cmd[i].kd  = cmd[i].kd;
        }
        cmd_pub_->Write(out);
        return true;
    }

    bool read_state(motion::RobotState &out) override {
        if (!has_new_) return false;           // 本拍没有新数据 -> 上层按超时处理
        out = latest_;
        has_new_ = false;
        return true;
    }

    bool switch_service(const std::string &s) override {
        if (s == "stand") return sport_->StandUp() == 0;
        if (s == "walk")  return sport_->BalanceStand() == 0;
        if (s == "damp")  return sport_->Damp() == 0;
        return false;
    }
    // ...
};

// 2) 上层代码一行不用改
UnitreeDdsPort port;
motion::RobotController rc(port, cfg);
if (!rc.start()) return -1;                    // 初始状态检查在这里面
rc.move_joints(target, 0.6, motion::Curve::SCURVE);
while (running) rc.tick();
```

## 四、上机前必须确认的几件事

1. **关节索引映射**：不同机型（Go2 / B2 / H1 / G1）电机数与顺序不同，
   必须按机型文档核对，**填错索引会直接打到别的关节上**
2. **控制频率**：本项目默认 500 Hz；Unitree 的控制周期要求以机型文档为准，
   超时未下发指令本体可能进入保护
3. **`kp`/`kd` 的量级**：先给**很小**的值试，确认方向对了再加。
   增益给太大 = 一瞬间满力矩，非常危险
4. **安全阈值**：本项目里的姿态/温度/心跳阈值都是**示例值**，
   必须按机型与实测数据重新标定（`SafetyLimits`）
5. **首次上机务必吊起来做**（挂在支架上，不让它真的走），确认方向与限位都对
6. **`CRC` 统计**：`LowState` 若带 CRC 字段，接进来统计；
   本项目已有"CRC 错误累计过多 -> 保护"的逻辑

## 五、本项目已经替你处理掉的坑

| 坑 | 本项目的处理 |
|---|---|
| 位置阶跃打坏减速器 | 上层给目标、下层走插值；序列首拍以**当前实际指令**为起点（这是修过的一个真 bug） |
| 传感器毛刺导致误急停 | 安全检查带**去抖**（连续 N 拍才确认） |
| 漏掉真实异常导致摔机器人 | 每拍**全量检查**（限位/速度/力矩/温度/姿态/角速度/通信/CRC/电量） |
| 故障后不知道切了什么状态 | 故障时**先切 damp 再返回错误**，并标记 `service_switched` |
| 急停被后续指令覆盖 | 急停**锁存**，必须显式 `clear_estop()` |
| 通信卡顿被当成"正常" | `read_state` 返回 false 会累积通话龄，超时即触发 `COMM_LOST` |
| 临时改目标导致跳变 | 轨迹可从**任意当前位置**重新起算（`start_from`） |
